# D0 — Documento de Definición del Problema

## 1. El problema

El minimarket **La Esquina**, ubicado en San Vicente de Cañete, registra sus ventas en un cuaderno de papel y controla el inventario mirando directamente los estantes. Esto genera dos problemas concretos:

- **No saben cuánto vendieron durante el día.** Las anotaciones manuales en el cuaderno dificultan sumar los montos y reconstruir el total diario, lo que impide saber si el día fue bueno o malo y tomar decisiones de compra.
- **Los productos se agotan sin darse cuenta.** Al depender de la inspección visual del estante, no existe un aviso temprano cuando un producto baja de una cantidad mínima. El cajero descubre la falta solo cuando un cliente pide el producto y ya no hay.

## 2. Usuario

- **Cajero del minimarket.** Es la única persona que usará la aplicación. Se encarga de registrar los productos, registrar las ventas a medida que ocurren y consultar lo vendido en el día.

No hay otros usuarios del sistema.

## 3. Proceso actual

1. Cuando llega mercadería, el cajero anota los datos del producto (nombre, precio, cantidad) en el cuaderno.
2. Cuando se realiza una venta, el cajero anota a mano el producto, la cantidad y el precio en el cuaderno.
3. Para saber el total del día, el cajero debe repasar el cuaderno y sumar manualmente cada venta.
4. Para saber qué productos hay, el cajero camina por los estantes y los revisa visualmente.
5. No existe ningún mecanismo de alerta cuando un producto está por agotarse.

## 4. Requisitos funcionales

### RF-1. Registrar producto

El cajero podrá registrar un producto nuevo indicando:

- **Código** (identificador único del producto).
- **Nombre** (descripción del producto).
- **Categoría** (grupo al que pertenece, por ejemplo: abarrotes, bebidas, limpieza).
- **Precio** (precio de venta unitario actual).
- **Stock actual** (cantidad de unidades disponibles en este momento).
- **Stock mínimo** (cantidad a partir de la cual se considera que el producto está bajo).

### RF-2. Listar productos y detectar stock bajo

El cajero podrá ver la lista de todos los productos registrados con sus datos. La lista debe marcar de forma visible cuáles productos tienen stock bajo, es decir, cuyo stock actual es menor o igual al stock mínimo.

### RF-3. Registrar venta

El cajero podrá registrar una venta indicando:

- **Producto** (seleccionado de los productos registrados).
- **Cantidad** (número de unidades vendidas).

El sistema debe:

- Calcular el total de la venta multiplicando la cantidad por el precio actual del producto.
- Guardar la fecha y hora en que se realiza la venta.
- Descontar del stock actual del producto la cantidad vendida.

### RF-4. Consultar ventas del día

El cajero podrá ver todas las ventas realizadas en el día actual, ordenadas por fecha y hora. La consulta debe incluir:

- Cada venta con su producto, cantidad y total.
- El total acumulado de todas las ventas del día.

## 5. Requisitos no funcionales

- **Aplicación web interna.** Se ejecutará en un navegador dentro del local del minimarket.
- **Uso sin conexión externa.** Debe funcionar en la red local del negocio sin depender de servicios de internet.
- **Rapidez.** Las operaciones de registro y consulta deben responder en segundos para no demorar la atención al cliente.
- **Simplicidad de uso.** La interfaz debe ser fácil de usar por una persona sin conocimientos técnicos.
- **Persistencia de datos.** Los productos y las ventas deben guardarse de forma que se conserven al cerrar y reabrir la aplicación.
- **Consistencia de datos.** La venta y el descuento de stock deben ejecutarse de forma que o ambos se realicen o ninguno, para que el inventario nunca quede desactualizado.
- **Seguridad de datos.** El sistema debe validar los datos ingresados y utilizar consultas SQL preparadas para evitar inyecciones SQL.

## 6. Reglas de negocio

- **RN-1.** No se permiten ventas con cantidad menor o igual a cero.
- **RN-2.** No se puede vender una cantidad mayor al stock disponible del producto.
- **RN-3.** No se permiten registrar productos con precio negativo.
- **RN-4.** No se pueden registrar dos productos con el mismo código; el código es único.
- **RN-5.** El registro de la venta y el descuento del stock deben realizarse de forma conjunta (atómica): si la venta se guarda, el stock se descuenta; si algo falla, la venta no se guarda y el stock no cambia.

## 7. Alcance

### Dentro del alcance

- Registro de productos con código, nombre, categoría, precio, stock actual y stock mínimo.
- Listado de productos con marca visual de stock bajo.
- Registro de ventas con cálculo de total, fecha y hora, y descuento de stock.
- Consulta de las ventas del día actual con total acumulado.

### Fuera del alcance

- Inicio de sesión o autenticación de usuarios.
- Roles o permisos diferenciados.
- Gestión de clientes.
- Facturación o emisión de comprobantes.
- Categorización avanzada, reportes históricos, gráficos u otras funciones no mencionadas.

## 8. Supuestos

> **Nota:** Los siguientes puntos son condiciones asumidas para el diseño de la aplicación. No son requisitos obligatorios; si alguna deja de cumplirse, el diseño deberá revisarse.

- La aplicación será usada por una sola persona (el cajero) en un equipo dentro del local.
- El precio del producto puede cambiar entre ventas; cada venta usa el precio que el producto tiene en el momento de la venta.
- El stock se gestiona únicamente desde la aplicación; no se realizan ajustes manuales externos que la aplicación deba reflejar.
- La fecha y hora de la venta se toma del sistema en el momento en que se registra.
- No se contempla edición ni eliminación de ventas ya registradas.
